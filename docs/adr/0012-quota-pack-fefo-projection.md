# 额度包：快照校准 + FEFO 推演

像素蛋糕类订阅的额度不是「每区间一份、区间末清零」，而是每期下发一个**额度包**（如每月 30 张、各包一年有效），多包叠加共存，订阅终止时全部失效。现有周期重置口径（TOTAL 快照 = 区间内已用、浪费 = 成本 × (1 − 使用率)）无法表达跨段存活的包与按包到期的浪费。为此额度型新增**包叠加**发放形态，产品只暴露剩余总张数（无包级明细），故以剩余快照校准 + FEFO 推演重建包级账本。

**形态与存储**：`Subscription.grantMode`（`RESET` 默认 / `STACKED`），仅 `usageKind = QUOTA` 时有意义——包叠加是额度型的子形态，不是第四种用量口径。包落独立 `QuotaPack` 表（`grantedAt`、`quantity`、`expiresAt`、`source: AUTO|MANUAL`）；每周期下发量复用 `quotaTotal`，有效期新增 `packValidMonths`（日历月，锚定下发日）。

**生成**：AUTO 包由生成器**读时对齐**（lazy reconcile）——每次推演/展示前把「订阅开始 → today」的应有 AUTO 包补齐、与锚点改写对账（未来包不物化）；`MANUAL` 行（赠送包）永不自动触碰。**手动模式无 AUTO**（无周期可推导），包全部手动录入。

**推演**：`expiresAt` 只存「下发 + 有效期」原始值，「停订即焚」在推演时以当前订阅到期日现场截断（续费后包自动复活）；包到期日排他（当天起不可用）。STACKED 的 `UsageRecord` 只收 TOTAL 剩余快照（不收 DELTA）；两次快照间总消耗 D = 期初剩余 + 期间发放 − 期末剩余，按 FEFO 先冲抵窗口内到期包的余额（计为浪费），其余计为消费——窗口内「消费先于到期」的宽厚假设给出浪费下限，误差由下一条快照吸收。

**计价与盈亏**：单张成本 = 发放段净额 ÷ 该段应发量；段内有 AUTO 包时 MANUAL 为零成本赠送包（到期只记数量浪费、金额为零，不摊薄付费成本基）；段内无 AUTO（手动模式，包全手动录入）时 MANUAL 即付费额度本身，应发量 = Σ MANUAL 数量——否则手动模式下所有浪费金额恒为零，停订即焚无法显形（ticket 02 实现期补充裁决）。verdict 浪费导向（与 QUOTA 同族）：`verdictAmount = −本区间已确认浪费`，展示最新快照余额（带快照日期与陈旧度提示，≥30 天变色）、下一到期包及 FEFO 模拟余额、区间/累计浪费。**池级口径**：额度池是账号级共享，用量/浪费不按受益人切片（`forUserId` 只切成本份额）。

**脚本**：STACKED 下用量脚本返回 `{ remaining }` 写 TOTAL 快照（RESET 契约 `{ used, total? }` 不变），守卫放宽为 QUOTA 任意形态。形态切换沿用向导的类型切换警告（警告不禁止）。

## Considered Options

- 手工逐包录入（下发/到期/各包余额）：产品 UI 只有剩余总数，包级数据不可观测，不可行。
- 周期重置口径加 rollover 标记：无法表达多包各自到期与「停订即焚」，区间末浪费的口径也与现实不符。
- 只记 DELTA 消费、不要快照：纯推演无校准，漏记一次消费即永久失真，且到期浪费仍需 FEFO 模拟，复杂度不省。
- 窗口内「到期先于消费」（保守假设）：浪费取上限，会高估浪费、低估用量价值；选宽厚假设是因为多数用户消费集中在包早期，且快照校准使两种假设长期收敛。
- 第四种 `usageKind = "PACK"`：所有 QUOTA 判断点（脚本准入、verdict、向导）爆炸式扩写，且概念上包叠加不是新的价值口径。
- `UsageRecord.kind = "GRANT"` 单表事件流：GRANT 行大半字段空置、污染记录管理页；包是有生命周期的实体，不是用量事件。
- 写时生成（eager）AUTO 包：无法覆盖纯时间推移产生的新包，最终仍需读时兜底，白赚双写一致性问题。
- 写入时封顶 `expiresAt`：续费改写订阅到期日（ADR-0001 核心机制）后要回补所有包，原始有效期已丢失，回补不出正确值。
- 快照 + 可选 DELTA 消费记录：只能改善「消费发生在窗口内到期日之后」这一极限情形的拆分精度，不值得贯穿 schema/推演/UI 的一条记录类型。
- 赠送包稀释计价（净额 ÷ 含赠送总量）：付费额度的浪费被赠送包摊薄，退订判据失真（同 ADR-0011 给折扣权益手填成本基的论证）。
- 价值导向 verdict（推算消费 × 替代单价 − 成本）：盈亏建立在窗口估计值上，不如快照钉死的浪费金额可信。
- 受益人按人切快照：共享池被多个观测者各记一遍即双倍计数，数学上不成立。
- 快照陈旧接入提醒系统（webhook/email）：对「该记账了」弱信号过度建设；浏览时原位提示已够。

## Consequences

- TOTAL 快照语义按发放形态分裂（已用 vs 剩余），解读入口必须先看 `grantMode`，混录禁止。
- 浪费确认时点从「区间末」变为「包到期日」，可能落在发放区间之后，跨段归因按到期所在区间展示；订阅终止时全部余额在终止日确认浪费。
- 脚本产出契约按形态分裂（`used` vs `remaining`），沙箱文档需同步。
- 手动模式 + STACKED 的用户录入负担高于周期模式，配置页应引导改用周期模式。
