# 移动端适配策略

Status: accepted

全站此前零响应式断点、固定 224px 侧边栏，移动端完全不可用。决定：以 `md`（768px）为唯一移动/桌面分界——≥md 保持现有桌面侧边栏布局（768–1024 中间档仅内容网格降列），<md 切换为移动导航：底部 tab 栏承载工作台 5 个高频页面，汉堡抽屉承载完整导航树（含权限门控的设置组）。表格采用混合策略：订阅/物品两个高频列表页在移动端渲染卡片视图（与视图切换功能共用卡片组件），工具型表格仅加横向滚动。触控底线：<md 可点元素 ≥44px、正文/数值 ≥12px，装饰性 mono 小字保持现状；桌面端布局与字号一律不变。适配范围含 login/register。

## Considered Options

- **单一 lg（1024）分界**：平板也用移动导航。实现只有一档更不易漏，但 768–1024 的屏幕被浪费，被否。
- **纯抽屉导航**：实现最省，但每次切页两步操作，不符合深度移动体验目标，被否。
- **全部表格卡片化**：体验最一致，但设置区低频页也要各设计一套卡片版式，工作量不成比例，被否。

## Consequences

- 此后所有新 UI 元素默认需在 <md 与 ≥md 两档下验证；新列表页优先提供卡片渲染以便移动端复用。
- 视图切换功能的卡片组件同时承担移动端列表渲染职责，两功能存在硬依赖（移动端适配排在其后）。
