# 面向中国大陆家庭用户：单一时区（东八区），不做国际化

subtrace 完全为中国大陆的家庭/个人用户构建。由此两条约定：

1. **不考虑国际化**：UI 文案、文档、术语一律中文；不引入 i18n 框架与多语言资源。
2. **全站时间一律东八区（Asia/Shanghai，无夏令时）**：日期构造、日界归一（"今天"、"到期日"、月度/年度报表切片）、显示格式化、cron 触发、内部天数运算，全部以北京时间为标准，不做任何跨时区兼容。"日期"定义为北京日历日零点对应的瞬间（如 2026-07-20 即 2026-07-19T16:00:00Z），由 `src/lib/dates.ts` 统一构造（parseDay/dayStart）与格式化（isoDay/fmtDateTime）。

理由：自部署单实例（ADR-0005）+ 用户全部身处同一时区，跨时区抽象（用户级时区设置、UTC 存储+本地显示的双轨心智）是纯成本；UTC 日界反而会造成"晚上 8 点后报表/提醒跳到明天"这类对用户不可解释的错位。代价：若用户移居其它时区需自行调整（部署环境单一约定即可覆盖）。
