# 成本装配收敛

Status: ready-for-agent

架构评审（2026-07-29）后续：候选 3 + 5 + 2。把「订阅成本视图」「区间成本装配」「实付净额」「表单解析」四组散落编排各收敛为单一模块。纯重构：不改变任何对外语义，不设新 ADR（无决策反转）。

## Problem Statement

维护者修改成本相关语义时，同一个概念要在多处同步修改：「某订阅今天覆盖哪些成本段、费率多少、我的份额多少」的编排在 dashboard、用量盈亏、订阅详情页、物品 TCO、报表五处各自拼装，覆盖谓词有三种写法；份额数学有两套平行实现，其中成本引擎的 shareOf 在生产代码零调用（死代码）；「一段时间每天摊多少」有两套算法，dashboard 趋势对每订阅每天重算整段序列（30×N 次）；实付净额公式散落四处；四个 server action 各自内联北京墙钟日期解析，绕过 ADR-0008 指定的统一构造入口。

## Solution

一个成本视图模块提供两个函数：点视图（某订阅某日的覆盖段/到期日/费率/份额切片/金额未知/推算段）与区间视图（一段时间内按天切片的摊销成本与分类聚合，报表的切片算法上提，dashboard 趋势改为消费它）；实付净额与区间实付聚合各一个函数，四处调用全迁移。表单解析模块提供日期/数字两个字段解析函数（日期委托 ADR-0008 的统一构造），四个 action 迁移。份额实现只留受益实体模块的一套，成本引擎死代码删除。

## User Stories

1. 作为维护者，订阅当日成本视图只有一个来源，以便改覆盖谓词或份额切片只动一处。
2. 作为记账用户，dashboard 趋势与报表的每日摊销由同一算法产出，以便两处数字永远一致。
3. 作为维护者，dashboard 趋势不再对每订阅每天重算成本段（30×N → N），以便页面装配随订阅数线性而非 30 倍增长。
4. 作为维护者，实付净额（金额 − 退款，未知按 0）只有一处定义，以便退款语义调整不会漏改调用方。
5. 作为维护者，成本引擎里没有被生产代码引用的死函数，以便引擎接口就是其真实契约。
6. 作为维护者，表单日期解析统一走 ADR-0008 的构造入口，以便墙钟约定变更不会四处漂移。
7. 作为记账用户，本次收敛不改变我能看到的任何数字与页面行为（重构非改语义）。

## Implementation Decisions

- 新模块：**订阅成本视图**（归属订阅概念，与订阅服务同目录）——`costView(订阅, 视角用户, 今日)` 返回全量视图（成本段序列、覆盖段、到期日、我的份额、当日费率、我的当日费率、金额未知标记、推算段行）；`costOverPeriod(…)` 返回区间按天摊销序列与分类/逐项聚合；`paidNet`/`paidInPeriod` 实付净额与区间聚合。
- 覆盖谓词收进成本引擎导出（覆盖段判定只一处）；成本引擎的 shareOf 删除（生产零调用）；受益实体模块的三个份额函数语义各异（视角聚合 / 单实体 / 行列表），保留原位。
- dashboard 的趋势循环、月度/年度实付，报表的区间切片，用量盈亏的覆盖段与份额切片，物品 TCO 的份额成本，订阅详情页的视图装配（含推算段行、实付合计）——全部迁移到新模块。
- 新模块：**表单解析**——`dayField`（委托既有 parseDay）与 `numField`（空串/非数 → undefined）；订阅、物品、用量、联合会员四个 action 的内联 parseDate/parseNum 删除迁移。提醒天数字段语法为订阅专属，留在订阅 action 原处。
- 报表模块保留页面装配职责（区间入参、视图模型出口），区间算法改为委托成本视图模块。

## Testing Decisions

- 好测试 = 只测新模块接口的外部行为；本次为行为保持重构，既有套件是第一不变式。
- 成本视图模块单测：DB fixture（参考受益实体、报表的既有服务测试）——覆盖段判定、份额切片（所有者/受益用户/纯设备分摊）、金额未知标记、推算段行、区间按天切片与既有报表算法等价、实付净额三态（正常/退款/未知）。
- 表单解析模块：纯函数，随 cost-engine 风格补边界用例（空串、非数、非法日期）。
- dashboard 不补直测（已与用户确认），其语义由 cost-view 测试 + 浏览器冒烟覆盖。
- 冒烟：dashboard、报表、订阅详情、物品详情四页数字与迁移前一致。

## Out of Scope

- 付费记录行渲染去重（评审候选 4，未选）。
- 任务注册表收敛（评审候选 6，未选）。
- 任何对外语义变化：覆盖谓词、份额数学、推算段规则均按现状原样收敛。
- 移动端适配与新功能。
