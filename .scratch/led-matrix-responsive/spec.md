# 点阵趋势屏响应式（led-matrix-responsive）

Status: ready-for-agent

2026-07-31 窄屏 bug 报告 + grilling 结论。两张单关注点 ticket，一票一 commit。

## 问题

dashboard「02 — 每日支出 / 30D」点阵趋势屏在窄视口不可见。根因（代码核实）：

- 30 天日值 3 倍插值 → **固定 88 列**，`gap=4px`，仅列间距占 348px
- 413px 视口下屏内容宽 ≈ 347px，$87 \times 4 = 348 > 347$ → `1fr` 列宽压到亚像素 → 点物理不可见，全黑屏
- 417px 时勉强可见但点为亚像素小点

## 决策（grilling 已对齐，2026-07-31）

1. **列数动态**：客户端组件 + ResizeObserver 测屏内容宽 $w$，$N = \lfloor (w+g)/(d_{min}+g) \rfloor$。删除 88 这个常数，不存在中间固定列数。
2. **重采样**：30 天日值直接重采样到 N 列（N>30 扩展、N<30 收缩，同一函数）。核 = **面积保持均值**（前缀和 + 区间积分）：总量守恒，收缩时尖峰摊薄不消失。否决点采样（收缩会丢尖峰，此 bug 的语义版）。
3. **像素常数**：$d_{min}=3$px，$g=4$px 固定，点径 9px 封顶（宽屏不加粗点、只加列），N 无上限、下限 8 列。
4. **纵向动态行数，屏高钉死**：$H = 100$px（8×9+7×4 精确值）。点径 $d=\min(\text{列宽},9)$，$\text{rows}=\lfloor(H+g)/(d+g)\rfloor$（347px 宽 → 14 行；宽屏 → 8 行，现状）。窄屏 = 同一块屏像素更密。行数零头沉屏底，黑底不可见，不补偿。
5. **首帧黑屏本地运算**：高度钉死 → SSR 输出固定 100px 纯黑带（零 CLS），点阵完全客户端渲染（mount 后测宽出点）。无 hydration mismatch、无默认帧闪烁。代价：JS 失败时该屏永久纯黑，可接受。
6. **柱高口径**：`max` 仍从**原始 30 天日值**算（`Math.max(...data, 0.01) * 1.1`），resize 只改量化粒度不改比例尺；柱高 = `round(v / max * rows)`，只取整一次（现状两次，新方案精度持平或更好）。点亮规则不变：柱身橙、柱顶白 `#F5F4F0`。

## 精度账（已确认）

- 垂直：只取整一次 ≤ 现状两次取整的误差；窄屏 rows↑ 分辨率反而更细
- 水平：N<30 时相邻天均值摊薄是不可避免的物理约束，面积保持保证总量守恒
- 唯一真实损失 = 水平收缩摊薄，已接受

## Out of Scope

- 「即将到期」2×8 小点阵（固定 size=4 非 stretch，窄屏不受影响）
- 其他页面 LedMatrix 用法（grep 确认仅 dashboard 两处）
