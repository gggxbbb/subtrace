# subtrace v1 — 订阅与物品开支追踪

## Problem Statement

我的周期性订阅（视频会员、网盘、coding plan、健身房）分散在各平台，每个都有不同的扣费周期、价格和续费方式。自动扣费经常被活动价手动续费打断（实付金额与标准价不同、到账时长不固定，如 B站扣一年实际到账 370 天），导致我既不知道下一个到期日是哪天，也不知道这些订阅每天到底花我多少钱。此外还有一次性购买的物品（电脑、耳机），我想知道它们的日均成本和"回本"进度。对于可量化用量的订阅（健身房去了几次、coding plan 用了多少），我想知道相对按次付费是赚了还是亏了。联合会员（如 88VIP）包含多个子会员，需要按原价比例分摊成本。Wallos 等现有工具只支持"周期+价格"推算，无法表达上述场景。

## Solution

一个自部署的多用户 Web 应用（类 Wallos），以**付费记录**为一等实体：每次真实付费（自动扣款、手动续费、活动价、退款）都记录金额与实际服务区间，到期日永远由最后一笔付费记录决定，未记账时按周期推算兜底。订阅、联合会员子会员、物品统一折算为"成本段"计算当日总日均；可量化订阅按"用量 × 替代单价 − 已摊成本"计算盈亏；多用户共享订阅按受益人权重分摊。UI 采用 Teenage Engineering 工业风（已定型的 dashboard 原型），品牌 logo 使用 Simple Icons。

## User Stories

1. 作为用户，我想用用户名密码注册登录，以便在自部署实例上拥有独立账号。
2. 作为首个注册的用户，我想自动成为管理员，以便管理后续用户。
3. 作为管理员，我想通过邀请链接创建新用户，以便实例不被公开注册滥用。
4. 作为用户，我想创建周期模式的订阅（名称、分类、周期单位日/周/月/年或固定天数、标准价、起始日、自动续费标记），以便系统自动推算到期日。
5. 作为用户，我想创建手动模式的订阅（不维护周期），以便管理价格/时长不固定的服务。
6. 作为用户，我想为订阅记一笔付费记录（实付金额、支付日期、服务起止、来源 auto/manual/promo、备注），以便修正到期日与成本。
7. 作为用户，我想在记付费时让系统按周期预填服务区间并可修改，以便快速录入常规续费。
8. 作为用户，我想在付费记录上登记退款金额，以便成本按净额计算。
9. 作为用户，我想在未记账的推算周期按标准价计入成本，以便不记账时日均不失真。
10. 作为用户，我想看到每个订阅的当前到期日和下次预计扣费日，以便安排资金。
11. 作为用户，我想为外币订阅记录原币金额和当时折算的主币种金额（汇率预填可改），以便历史成本不随汇率波动。
12. 作为用户，我想维护汇率表（自动 API 更新或手动钉住），以便录入外币时自动预填折算值。
13. 作为用户，我想创建联合会员（打包价、起止、多个子会员及各自原价），以便系统按原价比例把打包费分摊到每个子会员。
14. 作为用户，我想子会员成为完整订阅（独立周期、到期日、用量），以便分别追踪和提醒。
15. 作为用户，我想在原价未知时手填某子会员的分摊金额，以便处理赠品型子会员。
16. 作为用户，我想闲置子会员的成本照常在盈亏中显示净亏，以便评估是否退订联合会员。
17. 作为用户，我想登记物品（名称、金额、购买日期、可选预期寿命），以便计算日均成本。
18. 作为用户，我想物品按回本模型摊销（寿命内固定费率、超期摊至今日），以便看到"回本进度"。
19. 作为用户，我想登记物品卖出/报废（日期、残值），以便终止摊销并扣除残值。
20. 作为用户，我想为可量化订阅记录用量（手动逐条录入），以便计算盈亏。
21. 作为用户，我想为订阅填写替代单价（如健身房单次卡价），以便系统计算用量价值。
22. 作为用户，我想编写脚本定时从API同步用量（如coding plan），以便免除手动录入。
23. 作为用户，我想看到每个可量化订阅按服务区间计算的盈亏和每次实际成本，以便判断续费价值。
24. 作为用户，我想把订阅共享给其他受益人并设置权重（默认均分），以便成本按人分摊。
25. 作为受益人，我想只读查看共享订阅全貌，以便了解家庭开支。
26. 作为所有者，我想独占共享订阅的编辑权，以便账目责任清晰。
27. 作为受益人，我想各自的用量和盈亏独立计算，以便看出谁在用、谁纯亏。
28. 作为用户，我想在 dashboard 看到当日总日均（订阅分摊+物品摊销）、本月支出、年度累计，以便掌握开支水平。
29. 作为用户，我想看到未来到期列表（含自动/手动标记、金额、倒计时），以便不错过续费决策窗口。
30. 作为用户，我想看到用量盈亏红黑榜，以便一眼看出哪些订阅值、哪些亏。
31. 作为用户，我想看到近 30 天每日支出趋势，以便发现异常波动。
32. 作为用户，我想收到到期前提醒（站内、Webhook、邮件，默认前 7/3/0 天，可按订阅调整），以便在自动扣费前决定手动续费或退订。
33. 作为用户，我想把订阅标记为已取消（到期即止）或归档，以便保留历史但不计入活跃视图。
34. 作为用户，我想按分类筛选订阅和物品，以便分维度查看。
35. 作为用户，我想为只知道到期日、不知道实付金额的订阅直接记一笔金额未知的付费记录，以便老订阅不用考古账单也能纳入管理（成本段净额未知时不计入费率、UI 标注）。
36. 作为用户，我想额度型订阅（如 coding plan 的总额度/点数）能通过录入使用百分比、或总额度+已用额度来记录用量，也能用脚本自动获取，以便盈亏口径覆盖额度制产品。

## Implementation Decisions

- **技术栈**：Next.js（App Router）+ TypeScript + Prisma + SQLite；Tailwind v4；UI 图标 lucide-react，品牌 logo 用 simple-icons 的 SVG path 直渲（禁 emoji）；字体本地 fontsource 自托管（Space Grotesk + IBM Plex Mono），不用 next/font/google（构建期联网会在无代理进程下挂死）。
- **领域模型**：以 `CONTEXT.md` 术语为准；关键取舍以 ADR-0001（记录驱动到期日 + 双跟踪模式）、ADR-0002（联合会员子会员即完整订阅）、ADR-0003（共享订阅单一实体查询时分摊）、ADR-0004（货币录入快照）为准。
- **模块划分**：
  - 成本引擎（纯函数模块，无 DB/框架依赖）：成本段合成、到期日推算（日历周期锚定原始日 + 固定天数）、未记账周期按标准价补齐、退款净额、物品回本模型、按权分摊、按区间按人盈亏。
  - 仓储层（Prisma）：User/Invite/Subscription/Payment/Bundle/Share/UsageRecord/UsageScript/Purchase/ExchangeRate/NotifyChannel，schema 以 `docs/design.md` 草案为准。
  - Web 层（App Router 页面 + server actions/route handlers）：认证、CRUD、dashboard、设置。
- **UI**：dashboard 沿用已定型的 TE 风原型（`/prototype/dashboard` 转正）；侧边栏控制台布局；LED 点阵组件（趋势屏、urgency 条）；面板编号 + 全大写 mono 标签；主色橙 #FF5A00，底色 #E4E3E0，黑描边白面板。
- **认证**：用户名 + argon2 密码哈希 + session cookie；首个注册用户自动 ADMIN，此后仅凭邀请 token 注册。
- **提醒**：每日任务扫描到期日 − remindDays 命中的订阅，经用户启用的渠道（Webhook/邮件）投递；站内到期列表常显。
- **用量脚本**：用户 JS 在 node:vm 沙箱执行（受限 fetch、无 require、超时熔断），结果写入 UsageRecord；仅对信任用户开放。
- **环境配置**：`.npmrc` 设 `verify-deps-before-run=false`；`pnpm-workspace.yaml` 用 `allowBuilds`；`next.config.ts` 锁 `turbopack.root`。

## Testing Decisions

- **好测试的标准**：只测外部行为（给定输入断言输出），不断言实现细节；每条测试对应设计文档/ADR 中的一条可观察规则。
- **缝一：成本引擎**（Vitest 直测纯函数）——覆盖：记录驱动到期日、无记录时推算兜底、日历周期跨月锚定（1月31日月付）、固定天数周期、手动模式、实付≠标准价的日均、未记账周期按标准价补齐、退款净额、联合会员分摊比例、闲置子会员净亏、物品回本模型三态（寿命内/超期/卖出扣残值）、受益人权重分摊与全局重算、按区间按人盈亏、外币快照不被汇率修改影响。
- **缝二：仓储层**（Prisma + 独立测试 SQLite 数据库实测）——覆盖各实体的增删改查与关系完整性（级联删除、唯一约束、邀请 token 一次性）。
- **测试先行**：成本引擎按 TDD（红-绿-重构）推进。
- **无先例**：仓库无既有测试，本轮建立 Vitest 基建与约定。

## Out of Scope

- Wallos 或通用 CSV 数据导入（手动重录）。
- OAuth 登录、开放注册、密码找回邮件流。
- 移动端原生 App（响应式 Web）。
- 自动抓取订阅价格/到期日的爬虫。
- 多预算/多账本、银行账户同步。

## Further Notes

- 用量脚本沙箱不是强安全边界，多用户部署时只对信任用户开放该功能。
- 汇率 API 源需可配置（免费额度有限），自动更新失败时保留上次值并标记。
- 分摊权重与汇率修改均为"全局重算"语义（ADR-0003），历史报表会随后续修改变化，属预期行为。
- UI 原型保留在 `/prototype/dashboard` 供参考，正式实现重写于正式路由后删除原型路由。
