# 06 — 用量与盈亏（手动录入）

**What to build:** 可量化订阅的用量手动录入与盈亏。两类用量口径：**计数型**（逐条录入日期+数量，如健身房次数）；**额度型**（录入当前使用百分比，或总额度+已用额度，如 coding plan 点数）。替代单价设置、订阅详情页按服务区间展示盈亏（用量×替代单价−已摊成本）与每次实际成本、dashboard 红黑榜（盈亏排序）。

**Blocked by:** 03 订阅核心链路

**Status:** resolved

- [x] 可为订阅设置用量类型（计数/额度）、单位与替代单价
- [x] 计数型：逐条录入/删除用量记录（今天 +1 快记 + 补记）
- [x] 额度型：录入使用百分比（自动折算已用量）或总额度+已用额度
- [x] 详情页按服务区间显示盈亏与每次实际成本（当前区间实时、历史区间可回看）
- [x] Dashboard 红黑榜按盈亏排序，亏损标红

## Answer

UsageRecord（DELTA 增量 / TOTAL 快照）+ 订阅用量配置（usageKind/unit/altUnitPrice/quotaTotal）迁移；引擎 usageInPeriod（快照优先于增量）；用量服务 6 条仓储缝测试（健身房 9×30−217=53 场景复现）。
详情页双卡片：「用量录入」（无初始化门槛，类型/单位就地设定；本次用量/本次单价/当月总额度逐条可调，默认继承上一条记录；去重元组快捷钮）与「盈亏·当前区间」（四指标 + 历史记录）；dashboard 红黑榜面板。
计价模型：**单价跟记录走**（UsageRecord.unitPrice/quotaTotal 快照，空则回退订阅默认替代单价），天然支持多档位与变价。
顺手修一处 bug：actions 的 parseNum(null) 返回 0 导致手动模式订阅被写入 listPriceBase=0（即将到期金额错显 ¥0），已修并清理脏数据。67 条测试全绿，tsc 通过。
