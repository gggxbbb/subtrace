# 13 — 物品生命周期费用：追加事件 + 关联订阅

**What to build:** 物品买入后的两类后续费用，分开建模、统一呈现：

1. **一次性追加费用事件**（配件、维修等）：日期、金额（主币种快照）、类型、备注。计入物品净额、共用同一回本摊销窗口（手机 8000 + 维修 500 → 按 8500 摊）；维修可选同步延长预期寿命。
2. **关联订阅**（AppleCare、iCloud 等周期性费用）：就是普通订阅，通过受益实体机制（ticket 07：订阅的受益方可为物品）关联到物品，支持多设备按权重分摊。成本走订阅自己的成本段，不进物品净额。

物品详情页：TCO 视图 = 物品摊销 + 作为受益实体的订阅份额（持有期内），并列展示追加事件时间线与关联订阅列表；订阅详情页显示受益的物品。

**Blocked by:** 04 物品与回本模型

**Status:** resolved

## Answer

PurchaseEvent（ACCESSORY/REPAIR/OTHER + extendDays）：净额 = 买入 + Σ事件 − 残值，与买入价共用同一摊销窗口（purchaseNet 单一公式）；维修的 extendDays 延长摊销窗口与回本进度。事件 CRUD 面板 + 详情页时间线（买入 → 事件 → 卖出/报废/持有中）。关联订阅走 ticket 07 受益实体机制（成本独立成段），TCO 块分行展示份额/到期日/费率；订阅详情页受益面板列物品。卖出/报废残值从累计净额扣除（引擎测试钉死），关联订阅不受影响。

- [x] 可为物品追加一次性费用事件（日期、金额、类型、备注），计入净额统一摊销
- [x] 事件可编辑/删除，净额联动重算；维修可选延长预期寿命
- [x] 创建/编辑订阅时可把物品添加为受益实体（经 ticket 07 的共享机制）
- [x] 物品详情页 TCO = 物品摊销 + 关联订阅持有期摊销，分开展示两块
- [x] 详情页展示事件时间线（买入 → 维修 → …）与关联订阅（含其到期日/费率）
- [x] 卖出/报废时残值从累计净额（含事件）扣除；关联订阅不受影响
