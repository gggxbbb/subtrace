# UI 波次 B：空面板收高、用量记录按月聚合、数值字号层级

Status: ready-for-agent

来源：2026-08-26 全站 UI 走查排队的三项视觉打磨（波次 A spec 的 Out of Scope），经 2026-08-26 对真实演示数据的二次走查（1280px + 390px）落实为具体决策。全部纯呈现层，不动领域逻辑。

## Problem Statement

1. **空面板不收高**：grid 双列行内面板默认等高拉伸——详情页「付费历史 / 1」一行内容被左列表单拉成三倍高的死白；控制台「即将到期」与「红黑榜」互相拉伸。列表页「已归档 / 0」面板整条渲染却无信息量。
2. **用量记录平铺墙**：记录管理页逐条平铺，高频记录订阅（健身房一年 300 条）全是 `me +1 次` 的重复行，"哪个月用得勤"需要人肉数行。
3. **数值字号层级平**：订阅列表的日均（"该砍哪个"的核心决策数）、月均、盈亏同为 11px，权重无差；报表明细表摊销成本与日均同号。扫读时视线无落点。

## Solution

三项互相独立的呈现层改进：

1. **空面板收高**：grid 双列行 `items-start` 让面板高度自适应内容；空列表面板（归档 0 条）整个不渲染。
2. **按月聚合带**：用量记录管理页明细列表上方加按月聚合带（月 · 条数 · Σ 用量），点击月份回填从/到筛选下钻；仅计数型与省钱型。
3. **数值三档层级**：确立并应用三档——L1 hero（28px bold，KPI 卡/详情大数，已存在不动）；L2 行内主数（13px semibold tabular-nums）；L3 辅助数（11px muted tabular-nums）。订阅列表日均/盈亏升 L2、月均降 L3；报表明细摊销成本升 L2、日均降 L3。

## User Stories

1. 作为用户，我想空/短面板只占自己内容的高度，以便页面不被死白割裂。
2. 作为用户，我想归档为 0 时看不到归档面板，以便界面只呈现存在的东西。
3. 作为高频记录用户，我想在记录管理页先看到按月汇总（哪个月几次/省了多少），以便先定位月份再下钻明细。
4. 作为用户，我想额度型订阅不被强行按月求和，以便看到的每个数字都有意义（快照不可加）。
5. 作为用户，我想列表里一眼先看到日均与盈亏（大一号、有分量），月均等辅助数退后，以便扫读成本结构。

## Implementation Decisions

**空面板收高（ticket 01）**

- grid 双列行加 `items-start`：控制台 `dashboard/page.tsx` 的 04/05 行；订阅详情页 `[id]/page.tsx` 的双列行（01 记一笔/02 付费历史、03 用量/04 盈亏）。`Panel` 组件本身不动（flex 高度由父决定）。（实施时更正：控制台 06 回本进度与 07 订阅明细实为整宽堆叠、无共享 grid 行，不存在拉伸问题，ticket 01 已如实记录。）
- 归档 0 条不渲染：订阅列表 `ArchivedList` 与物品列表 `ArchivedPurchaseList` 的调用点加数量判断，`archived.length === 0` 时整个 Panel 不渲染（面板内空态文案随之成为死代码，删除）。
- 其余空态 strip（`px-4 py-6 text-center`）保持原样——它们已在内容盒内，收高由 `items-start` 完成。

**按月聚合带（ticket 02）**

- 纯函数 `monthlyUsageAggregation(rows)`（`lib/usage/`）：输入记录管理页已加载的全量行，输出按月分组 `{ month: "YYYY-MM", count, total }` 降序。计数型 `total = Σ quantity`；省钱型同函数（quantity 即已省金额，渲染层换单位）。北京墙钟月份边界（`isoDay` 截取前 7 位即可，记录日期本身已是北京日）。
- 渲染：记录管理页筛选条与明细之间插入聚合带（表格或行列表：`2026-08 · 7 条 · Σ 7 次`）。点击月份 = `<a href>` 回填 `from=月初&to=月末`（GET 下钻，沿用现有筛选机制，无新状态）。当前筛选已落在某月时该月行高亮。
- 仅 `usageKind === COUNT | SAVINGS` 渲染；QUOTA（含 STACKED）快照不可加，不渲染聚合带；kind=TOTAL（快照）筛选下同样不渲染——快照不可加（story 4）。
- 受益人筛选与聚合带正交：聚合带跟随当前筛选结果聚合（选了受益人就只聚合他的），不额外加维度。
- 明细列表保持平铺不动（编辑/删除入口在明细行上）。

**数值字号层级（ticket 03）**

- 三档定义（写入 `CONTEXT.md` 无必要——呈现层约定，注释落在 te.tsx 或本 spec）：
  - L1 hero：`text-[28px] font-bold tabular-nums`（KPI/详情大数，现状保留）
  - L2 行内主数：`text-[13px] font-semibold tabular-nums`
  - L3 辅助数：`text-[11px] text-muted tabular-nums f-mono`
- 订阅列表桌面表格：日均列 L2；盈亏列 L2（保留盈青/亏红/未知灰配色）；月均列降 L3。移动卡片同步（`订阅` 卡片内的同样三个数）。
- 报表明细表（`reports/page.tsx` 03 明细）：摊销成本列 L2；日均列降 L3。
- 不动：详情页 KPI/盈亏面板（大数层级已成立）、控制台红黑榜（金额已 13px semibold）、表单/标签/9-10px 装饰 mono。

## Testing Decisions

沿用仓储缝测试风格；本批纯视觉项（01/03）无自动化，浏览器 1280/390 双宽度冒烟。

- **monthlyUsageAggregation（纯函数）**：月分组与 Σ；月降序；跨受益人合并；省钱型同路径（quantity 即金额）；空数组；跨年（2025-12 / 2026-01 分桶不错位）。
- **冒烟**：详情页双列行短面板不再拉伸（付费历史 1 行 vs 表单）；订阅列表无归档时无归档面板；记录管理页聚合带点击下钻回填筛选；列表/报表字号双宽度截图对比。

## Out of Scope

- 付费记录的聚合（年付一年一条，无量级问题）。
- 详情页盈亏面板右侧近期记录预览（保留平铺，链接到管理页）。
- 记录分页/虚拟滚动（聚合带先解决扫读；性能问题出现时单独立项）。
- 控制台、物品页、联合会员页的字号调整（列表/报表验证三档后再推广）。
- 暗色模式专项（语义 token 双主题已覆盖）。
