# 01 — FEFO 推演引擎（纯函数模块）

**What to build:** 额度包的推演核心作为一个独立纯函数模块交付（无 schema、无 UI，同 01-cost-engine 先例，独立可验证）：输入额度包列表（下发日/数量/到期日/来源 AUTO|MANUAL）、剩余总量快照、订阅到期日、单张成本函数，输出包级账本——最新快照校准余额（带快照日期）、下一到期包及其 FEFO 模拟余额（到期预警）、累计推算消费、按到期日归集的浪费（数量+金额）。推演规则按 ADR-0012：包有效到期日 = min(包到期日, 订阅到期日)，排他；两次快照间总消耗 D = 期初剩余 + 期间发放 − 期末剩余，按 FEFO 先冲抵窗口内到期包的余额（计浪费），其余计消费（消费先于到期的宽厚假设）；订阅终止日全部余额确认为浪费；赠送包零成本（只记数量浪费，金额为零）。接口类型形状以 spec（.scratch/quota-pack/spec.md）内联的 `projectPackLedger` 契约为准。

## Answer

**实现位置**：`src/lib/usage/pack-ledger.ts`（引擎）+ `src/lib/usage/pack-ledger.test.ts`（12 例全绿）。落在 usage 域而非 cost-engine 同级新目录：消费方是 usage 服务（ticket 02 的 `getUsageVerdict`），包账本是额度用量域概念；cost-engine 先例指的是「独立纯函数模块可验证」的交付形态，不是物理位置。

**关键决策**：
- 单趟事件模拟，推演边界 = 最新快照日。窗口 (prev, t]：期间发放满额入池 → 有效到期日 ≤ t 的包按 FEFO 模拟余额焚毁（计浪费）→ 快照校准。确认浪费只发生在快照覆盖的时间轴内；快照之后的消费不可知，故停订即焚的全量浪费需有一条 ≥ 订阅到期日的快照才被确认（服务层可在订阅到期后合成 remaining=0 快照，ticket 02 决策点）。
- 「宽厚假设（浪费下限）」的操作化：每次快照校准把漂移（模拟余额 − 实测剩余）计为消费，按 FEFO（先到期先扣，同到期先下发先扣）划扣——先到期的包余额始终最小，到期焚毁的浪费即为下限；窗口内到期包余额先计浪费、其余计消费，与 ADR-0012 公式一致。
- 有效到期日 = min(expiresAt, subscriptionExpiry)，排他（到期日当天的快照视包为已焚毁；到期日前一天仍存活进 nextExpiry 预警）。订阅终止全量浪费由截断自然推出；续费复活 = 同一输入改 subscriptionExpiry 重算（测试对比 06-01 vs 2027-06-01 两种截断结果）。
- 首快照前的包命运不可知：已到期包静默丢弃（不计浪费），存活包满额入池后首校准漂移计消费——与 D 公式在初始窗口的延伸一致。
- 校准负漂移（剩余无发放回升）：反向 FEFO 回补（先保晚到期包、封顶多发数量，尾差压最晚包），保证校准后 Σ余额 = 实测剩余；不冲减累计推算消费。
- 赠送包零成本不在引擎内特判：amount = 数量 × unitCostOf(pack)，MANUAL=0 由调用方回调表达（spec 契约注释即此语义）；浪费按确认日归集（同日多包合并 quantity/amount）。
- nextExpiry.projectedBalance = 最新校准后该包的 FEFO 模拟余额（未来消费不可知，不做消耗速率外推）。

**对 spec 契约的一处偏差**：`balanceAt` 类型为 `Date | null`（spec 写的是 `Date`）——空快照时无快照日期可填，null 是唯一诚实值；ticket 验收明确要求空快照边界不崩。

**坑**：
- ADR 公式「先冲抵窗口内到期包余额计浪费」字面与「消费先于到期给浪费下限」看似冲突：下限体现在跨窗口的 FEFO 校准划扣（先到期的包先被消耗光），窗口内到期包烧的是校准后的模拟余额；两者自洽，测试用对照数字（A 烧 20 而非保守口径的 30）锁定。
- 排他边界的同刻排序：同一快照日先处理到期焚毁再校准（窗口含右端点），保证到期日当天快照观测的是焚毁后的现实。
- 输入防御性拷贝+排序（packs 按到期日、snapshots 按日期），不突变入参；乱序输入有测试锁定。
