# 额度包：包叠加形态的额度型用量（像素蛋糕类）

Status: ready-for-agent

Grilling 产出：决策全文见 ADR-0012 与 CONTEXT.md「额度包 / 发放形态 / 用量」词条（2026-08-03）。十二项裁决（Q1–Q12）已在 grill 会话中逐项确认。

## Problem Statement

像素蛋糕这类订阅的额度不是「每个服务区间一份、区间末清零」，而是每期下发一个**额度包**：每月下发 30 张，每个包独立一年有效，多包叠加共存（峰值 360 张可用），订阅终止时所有未用完的包立即失效（停订即焚）。现有额度型（QUOTA）的三个隐含假设全部与之冲突：verdict 只取当前成本段内的快照（包跨段存活被切断）；总额度假设为单期一份（实际可用是 Σ 未过期包）；浪费假设为区间末未用即浪费（实际浪费只发生在包到期或订阅终止时）。结果是这类订阅在系统里无法表达余额、无法识别到期浪费，「还剩多少、什么时候过期、浪费了多少、该不该续」全部没有答案。

## Solution

额度型新增**包叠加（STACKED）发放形态**（ADR-0012）：系统按订阅周期自动生成额度包账本（每月 1 日 +30 张、次年同日到期），用户只需不定期录入产品界面可见的**剩余总张数**快照；系统用 FEFO（先到期先扣）推演把两次快照间的总消耗拆分为「消费」与「到期浪费」——窗口内到期包的模拟余额计为浪费，其余计为消费，误差由下一条快照自动吸收。盈亏面板浪费导向：显示最新快照余额（带快照日期与陈旧度提示）、下一到期包及模拟余额（到期预警）、本区间与累计浪费金额。订阅终止时全部余额在终止日确认为浪费；续费后包自动按新到期日「复活」。赠送包等活动额度可手动补录（零成本，只记数量浪费）。用量脚本可返回 `{ remaining }` 自动同步剩余。

## User Stories

1. 作为用户，我想在用量向导选择额度型后进一步选发放形态（周期重置 / 包叠加，含适用场景说明：流量机场用前者、像素蛋糕用后者），以便额度语义匹配真实产品。
2. 作为用户，我想选包叠加后填「每周期下发量」（复用现有总额度字段，标签随形态变化）与「包有效期（月）」，以便系统能推导发放计划。
3. 作为用户，我想系统按订阅的锚定日期与计费周期自动生成额度包（周期模式），以便不用每月手工登记下发。
4. 作为用户，我想生成的包只覆盖到今天为止（未来包不物化），以便「下期将下发」的展示与已发生事实不混淆。
5. 作为用户，我想录入一笔带服务止期的付费记录（锚点改写）后，未来的自动生成包自动按新锚点对账重排，以便发放计划与真实付费一致。
6. 作为用户，我想手动模式订阅也能用包叠加，但明白系统无法推导发放计划、包需全部手动录入（配置页给出改用周期模式的引导），以便概念边界清晰。
7. 作为用户，我想手动补录赠送包/活动包（下发日、数量、到期日），以便厂商送的额度也进入余额推演。
8. 作为用户，我想查看、编辑、删除手动补录的包，以便记错能改；自动生成的包不允许手改（随对账重排）。
9. 作为用户，我想录入「剩余总张数」快照（照抄产品界面的剩余数），以便校准推演；录入负担只是不定期抄一个数。
10. 作为用户，我想包叠加下的记录页不出现「增量/本次用量」录入入口（只收剩余快照），以便语义不混淆。
11. 作为用户，我想看到当前余额 = 最新快照值及其快照日期，以便明确数字的时效（快照后的消费不可知，不假装知道）。
12. 作为用户，我想快照超过 30 天未更新时看到变色提示（详情页与大盘原位展示，无推送），以便记得校准。
13. 作为用户，我想看到下一到期包的数量与 FEFO 模拟余额（到期预警：「9 月 15 日有 30 张到期，按当前消耗预计剩 12 张」），以便在到期前突击使用。
14. 作为用户，我想盈亏面板显示本区间已确认浪费金额（区间内到期包的未用余额 × 各包单张成本）与累计浪费，以便回答「浪费了多少」。
15. 作为用户，我想盈亏判定值 = −本区间浪费金额（与周期重置形态同族同口径），以便 dashboard 红黑榜照常排序。
16. 作为用户，我想单张成本 = 发放段净额 ÷ 该段应发数量，以便浪费金额真实反映付费成本。
17. 作为用户，我想赠送包到期只记数量浪费、金额为零（不摊薄付费额度的单张成本），以便退订判据不失真。
18. 作为用户，我想订阅终止（到期日过、不再续费）时所有未用完余额在终止日确认为浪费，以便「停订即焚」的损失显形。
19. 作为用户，我想补录一笔续费后包按新订阅到期日自动「复活」（推演时截断，不改包表数据），以便断缴后续订的口径正确。
20. 作为共享订阅的所有者，我想包叠加的余额与浪费按池级展示（不按受益人切片——池是账号级共享），受益人视图只按权重切成本份额，以便分摊语义不双重计数。
21. 作为信任用户，我想用量脚本在包叠加形态下返回 `{ remaining }` 即可自动写剩余快照（周期重置契约 `{ used, total? }` 不变），以便有 API 的产品零录入负担。
22. 作为用户，我想切换发放形态时看到与切换用量类型同款的失真警告（警告不禁止），以便知晓历史快照会被按新语义解读。
23. 作为用户，我想历史区间可回看浪费确认（浪费按到期所在区间归因），以便复盘上一个订阅年哪些包浪费了。
24. 作为用户，我想包到期日当天起不可用（与订阅到期日同款排他约定），以便口径与系统其他日期一致。

## Implementation Decisions

- **Schema**：`Subscription` 新增 `grantMode`（`"RESET"` 默认，可空即 RESET，存量 QUOTA 订阅零迁移）与 `packValidMonths Int?`（日历月，锚定下发日）。下发量复用 `quotaTotal`（STACKED 下读作每周期下发量）。新表 `QuotaPack`：`grantedAt`、`quantity`、`expiresAt`（存「下发+有效期」原始值，不做停订截断）、`source: AUTO|MANUAL`、订阅级联删除。
- **生成器（读时对齐）**：每次推演/展示前，按锚定日期 + 计费周期 + `quotaTotal` + `packValidMonths` 推导「订阅开始 → today」的应有 AUTO 包，与库中 `source=AUTO` 行对账：缺的补、锚点改写后对不上的删了重生成；已过去的包不动（历史已被快照校准）；`MANUAL` 行永不触碰。手动模式订阅跳过生成（守卫在配置层）。
- **推演引擎（新纯函数模块，唯一新缝）**：输入包列表 + 剩余快照 + 订阅到期日 + 成本段，输出包级账本。接口形状（决策即此类型）：

  ```ts
  // 输入：packs 按 expiresAt 排序；snapshots 按 date 排序
  projectPackLedger(input: {
    packs: { grantedAt: Date; quantity: number; expiresAt: Date; source: "AUTO" | "MANUAL" }[];
    snapshots: { date: Date; remaining: number }[];
    subscriptionExpiry: Date | null;   // 停订即焚截断，null = 未到期
    unitCostOf: (pack) => number;      // AUTO=发放段净额/应发量；MANUAL=0
  }): {
    balanceAt: Date;                   // 最新快照日期（余额时效）
    balance: number;                   // 最新快照校准余额
    nextExpiry: { date: Date; quantity: number; projectedBalance: number } | null;
    consumptionInferred: number;       // 累计推算消费
    waste: { date: Date; quantity: number; amount: number }[];  // 按到期日归集
  }
  ```

  推演规则：包有效到期日 = `min(expiresAt, subscriptionExpiry)`，排他；两次快照间总消耗 $D = R_0 + G - R_1$，按 FEFO 先冲抵窗口内到期包的余额（计浪费），其余计消费（消费先于到期的宽厚假设，ADR-0012）；订阅终止日全部余额确认为浪费。
- **用量服务**：`addQuotaSnapshot` 增加 STACKED 分支（`remaining` 入参写 TOTAL，守卫形态一致；STACKED 拒绝 DELTA 录入与百分比入参）；`getUsageVerdict` 新增 `PackVerdict` 变体（浪费导向：`verdictAmount = −本区间确认浪费`，携带余额+快照日期+陈旧天数、到期预警、区间/累计浪费、`costUnknown` 透传）；受益人切片在 STACKED 下只切成本份额、用量/浪费保持池级（忽略 `forUserId` 的用量过滤）。
- **配置服务**：`setUsageConfig` 扩展 `grantMode` / `packValidMonths`（仅 QUOTA 可设；手动模式 + STACKED 时清空两字段并标记需手动录包）；形态切换复用向导警告模式（警告不禁止）。
- **脚本**：沙箱产出契约按形态分裂——STACKED 接受 `{ remaining }` 写 TOTAL 剩余快照；RESET 契约 `{ used, total? }` 不变；`saveScript` 守卫从「仅 QUOTA」放宽为 QUOTA 任意形态；沙箱文档同步。
- **UI**：用量向导额度型卡片后加形态选择与 STACKED 字段（每周期下发量、有效期月数）；用量录入卡加 STACKED 分支（单字段「剩余总量」+ 上一条快照参考）；盈亏卡加 PackVerdict 分支（余额+快照日期、陈旧度变色、到期预警、区间/累计浪费，隐藏使用率/用满提示）；用量记录页 STACKED 下列标签「剩余」、隐藏增量录入；新增包管理卡（手动包增删改、AUTO 包只读列表）；dashboard 红黑榜按 `verdictAmount` 纳入现有排序，无特殊分支。

## Testing Decisions

好测试标准：只测外部行为（推演输出、服务返回值、落库状态、判定输出），不测实现细节；沿用仓储缝测试风格（真实 prisma 测试库，fileParallelism: false）。三条缝已与用户对齐：

- **推演引擎缝（新，纯函数）**：FEFO 拆分（消费先于到期的宽厚假设）；快照校准吸收误差；包到期排他边界；停订即焚截断与终止日全量浪费；续费后复活（改 subscriptionExpiry 重算）；赠送包零成本（数量浪费、金额为零）；单张成本按发放段计价；空快照（只有包）与空包边界。先行例子：`cost-engine/index.test.ts` 的 verdict / usageInPeriod 用例风格。
- **用量服务缝（现有，prisma 测试库）**：生成器读时对齐（按月补齐、锚点改写重排、MANUAL 行不动、手动模式不生成）；`addQuotaSnapshot` STACKED 分支（remaining 落库、DELTA/百分比拒绝）；`getUsageVerdict` PackVerdict 装配（浪费金额、池级忽略 forUserId 用量切片、成本仍乘份额、costUnknown）；脚本 `{ remaining }` 写快照（RESET 契约回归不破坏）。先行例子：`usage/service.test.ts`、`scripts/service.test.ts`。
- **冒烟**：dev server 起服务，浏览器走「像素蛋糕设包叠加（每月 30 张 / 12 个月）→ AUTO 包生成 → 录两条剩余快照 → 到期预警与浪费显示 → 录入停付 → 停订即焚浪费确认 → 红黑榜出现」全流程。

## Out of Scope

- STACKED 下的 DELTA 消费记录（Q7 已决：只收剩余快照；宽厚假设 + 快照校准已够）。
- 价值导向盈亏（推算消费 × 替代单价 − 成本；Q9 已决浪费导向，STACKED 不收替代单价）。
- 受益人按人切用量/浪费（Q10 已决：共享池双倍计数，数学上不成立）。
- 快照陈旧的推送提醒（webhook/email；Q12 已决只做原位展示）。
- 像素蛋糕等具体厂商的 API 对接（脚本机制已是通用入口，脚本由用户编写）。
- 手动模式订阅的 AUTO 生成（Q5 已决：无周期可推导，包手动录入）。
- 既有 RESET 订阅的任何迁移（`grantMode` 空即 RESET，行为不变）。

## Further Notes

- 窗口内「消费先于到期」是宽厚假设：浪费取下限。厂商实际扣减顺序即便不同，只要总余额一致，长期由快照校准收敛（ADR-0012）。
- 停订后「断缴再续」的场景无需特殊处理：旧包在旧终止日确认浪费，新周期的新包从续费后的区间重新发放，第一条新快照重新校准。
- 形态切换后历史 TOTAL 快照被按新语义解读（已用 ↔ 剩余），盈亏会失真——警告已覆盖，这是用户明确选择的代价。
- 与并行 spec 无文件冲突面预判：本 feature 触及 schema、usage 服务、cost-engine 同级新模块、订阅详情 UI、脚本服务；与 ui-* / dark-mode 类 spec 的冲突面在详情页组件，量级小。
