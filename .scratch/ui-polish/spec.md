# UI Polish — 使用反馈批次

Status: ready-for-agent

来源：维护者实际使用反馈（2026-07-27），经 `/grill-with-docs` 十条决策收敛、`/to-spec` 成稿。

## Problem Statement

日常使用 subtrace 后暴露一批 UI 可用性问题：窄宽度下卡片文字溢出破版；整个应用没有任何移动端适配（零响应式断点，固定侧边栏在手机上不可用）；订阅页只有表格、物品页只有卡片，无法按场景切换视图；已添加的通知渠道（Webhook/Email）不能编辑，改一个 URL 只能删除重建；订阅和物品列表没有排序和筛选，条目一多难以定位；新建订阅的单页长表单字段密集、条件字段混杂，不如启用用量跟踪那样的分步向导清晰。

## Solution

一组六个相互独立的 UI 改进（详见 User Stories 与 Implementation Decisions）：卡片文字截断根治溢出；全站深度移动端适配（底部 tab + 抽屉导航、混合表格策略、触控底线）；订阅/物品页卡片↔列表视图切换；通知渠道原地编辑；列表页工具栏排序与筛选；新建订阅改为四步向导。

## User Stories

1. 作为用户，我希望面板和卡片中的长文字在宽度不足时被截断并显示省略号，以便布局不错位、不破版。
2. 作为用户，我希望被截断的文字能通过悬浮提示看到完整内容，以便截断不丢失信息。
3. 作为手机用户，我希望在移动端有底部 tab 栏快速切换工作台五个页面（控制台/订阅/联合会员/物品/报表），以便单手高频操作。
4. 作为手机用户，我希望通过汉堡抽屉访问完整导航树（含设置组），以便低频页面也可达。
5. 作为平板用户，我希望 ≥768px 时看到桌面侧边栏布局，以便利用更大屏幕。
6. 作为手机用户，我希望订阅和物品列表在移动端默认以卡片视图呈现，以便不横向滚动就能浏览。
7. 作为手机用户，我希望工具型表格（设置、任务、支付记录等）可以横向滚动，以便查看完整数据。
8. 作为手机用户，我希望所有可点元素至少 44px、正文和数值至少 12px，以便准确点按和阅读。
9. 作为手机用户，我希望登录/注册页同样适配移动端，以便从手机完成完整使用闭环。
10. 作为桌面用户，我希望移动端适配完全不改变 ≥1024px 的现有布局与字号，以便保持我已习惯的 TE 风格界面。
11. 作为用户，我希望订阅页能在表格（列表）和卡片两种视图间切换，以便按场景选择浏览密度。
12. 作为用户，我希望物品页能在卡片和表格（列表）两种视图间切换，以便按场景选择浏览密度。
13. 作为用户，我希望视图选择按页记住（localStorage），以便刷新后保持我的偏好。
14. 作为用户，我希望订阅页桌面默认列表视图、物品页桌面默认卡片视图（维持现状），以便适配不打扰既有习惯。
15. 作为用户，我希望通知渠道可以原地编辑名称与配置，以便改 URL、改 SMTP 密码不必删除重建。
16. 作为用户，我希望编辑渠道时类型（Webhook/Email）不可更改，以便配置语义始终明确。
17. 作为用户，我希望编辑邮箱渠道时密码留空表示保留原密码，以便不必每次重输密钥。
18. 作为用户，我希望订阅页能按名称/到期日/日均/月均排序，以便快速找到最贵或最急到期的订阅。
19. 作为用户，我希望物品页能按名称/购入日期/日均成本/金额排序，以便回顾开支结构。
20. 作为用户，我希望两页都能按分类、状态和关键字筛选，以便条目多时快速定位。
21. 作为用户，我希望排序和筛选状态体现在 URL 中，以便刷新、分享链接后状态不丢。
22. 作为用户，我希望排序筛选工具栏在卡片和列表视图下都可用，以便视图切换不丢上下文。
23. 作为用户，我希望新建订阅是分步向导（基本信息→模式与周期→首笔与提醒→确认），以便每步只面对一组相关字段。
24. 作为用户，我希望向导中手动模式下周期与价格步骤自动瘦身，以便不被无关字段干扰。
25. 作为用户，我希望向导最终创建的订阅与原单页表单能力完全一致（周期/手动模式、日历周期/固定天数、标准价、首笔付费、提醒天数），以便迁移不丢功能。
26. 作为用户，我希望向导的视觉与分步模式与启用用量跟踪向导一致，以便产品内交互语言统一。

## Implementation Decisions

**移动端适配（最大的一项，记录为 ADR-0009）**

- 断点：`md`（768px）为移动/桌面分界。≥md 显示现有固定侧边栏布局；<md 使用移动导航。768–1024 中间档保留侧边栏，内容网格降列（如物品卡片 3→2 列）。
- 移动导航：底部 tab 栏放工作台 5 项；左上角汉堡打开抽屉承载完整导航树（含设置组及其 admin/trusted 权限门控，门控逻辑复用现有侧边栏的 props）。
- 表格策略（混合）：订阅/物品列表页在 <md 默认渲染卡片视图（直接复用视图切换功能产出的卡片组件）；设置、任务、支付记录、用量记录等工具型表格包 `overflow-x-auto` 横滚容器。
- 触控与字号底线：<md 时所有交互元素（按钮、tab、行操作、链接块）最小触控目标 44px；正文与数值文字 ≥12px；装饰性 mono 标签（9–10px 的 index/标签）保持现状。桌面端字号与布局一律不变。
- 适配范围覆盖 login/register 与全部 (app) 路由，含控制台（KPI 网格、LED 点阵图需响应式）。

**卡片溢出修复**

- 策略：单行截断 + 省略号 + `title` 属性悬浮提示，不换行。
- 在共享组件层根治：`Panel` 头部标题、`Kpi` 数值/标签加截断；页面级卡片（物品网格卡片名称、联合会员面板长标题等）补 `min-w-0`/`truncate`。

**视图切换**

- 订阅页与物品页各加一个卡片↔列表切换（lucide 图标按钮，与排序筛选工具栏同行）。
- 默认：桌面端订阅=列表、物品=卡片（维持现状）；<md 默认卡片。任何端可切换。
- 偏好按页存 localStorage（如 `subtrace:view:subscriptions` / `subtrace:view:purchases`），不改 schema。
- 页面为服务端组件，切换器为客户端组件包裹；需处理 localStorage 读取的 hydration 闪烁（如挂载后校正）。
- 订阅卡片视图字段：名称、分类、周期、到期日、日均/月均、状态 LED；物品列表视图字段：名称、分类、购入日期、金额、日均、持有天数/回进度、状态。

**通知渠道编辑**

- 每行渠道增加"编辑"操作，打开与创建表单同构的预填表单；新增 `updateChannelAction` 服务端动作与 `updateChannel` 服务函数，校验逻辑与创建一致。
- 类型不可改（WEBHOOK/EMAIL 固定）；`enabled` 状态编辑后保留。
- 邮箱渠道的 `pass` 字段：留空 = 保留原密码。

**排序与筛选**

- 形态：列表面板上方工具栏——排序字段下拉 + 升/降切换 + 分类下拉（取值自现有数据）+ 状态下拉 + 关键字输入（名称包含，大小写不敏感）；与视图切换按钮同行。
- 状态筛选口径：订阅 = 正常 / 临期（≤14d）/ 已过期 / 已取消（派生自到期日，与列表状态列一致）；物品 = 使用中 / 已卖出 / 已报废。
- 状态由 URL searchParams 驱动（可分享、可刷新）；日均/月均为成本引擎派生字段，排序/筛选统一在计算后的行集合上进行。
- 排序与筛选对卡片、列表两种视图同时生效；归档区不受影响。

**新建订阅向导**

- 四步：①基本信息（名称/分类/起始日期）②模式与周期（跟踪模式选择；周期模式展开周期形态+字段、标准价、币种、自动续费）③首笔与提醒（周期模式显示首笔付费块；提醒天数）④确认（摘要+提交）。
- 手动模式下②无周期/价格字段、③无首笔付费块，步骤自然瘦身。
- 视觉与分步模式复用用量跟踪向导（UsageWizard）的模式：步骤指示器、上一步/下一步、逐步校验。
- 最终一次性提交现有 `createSubscriptionAction`（字段全集不变，能力零丢失）；`?error=1` 错误提示路径保留。
- 完全替换现有单页表单；订阅编辑页不动。

**执行顺序（ticket 拆分见 Further Notes）**

01 溢出 → 03 视图切换 → 05 排序筛选 → 06 向导 → 02 移动端；04 渠道编辑独立可插任意位置。02 最后做，等 03/05/06 的新 UI 元素定型后一次适配。

## Testing Decisions

- 好的测试只测外部行为，不测实现细节；本批次大部分为纯 CSS/DOM 改动，不为视觉验证引入组件测试栈（仓库无先例）。
- **渠道更新**：`updateChannel` 服务函数单测（含校验失败、保留 enabled、pass 留空保留原值）。Prior art：`src/lib/notifications/service.test.ts`。
- **排序/筛选**：排序与筛选逻辑抽为纯函数（作用于计算后的行集合），单测覆盖各排序字段升降序、状态/分类/关键字筛选及组合。Prior art：`src/lib/reports.test.ts` 风格的纯函数测试。
- **向导**：提交链路仍走 `createSubscriptionAction`，由现有 `subscriptions/service` 测试覆盖；向导交互手动冒烟。
- **溢出/移动端/视图切换**：浏览器多宽度（375/768/1024/1440）手动冒烟，不写自动化测试。

## Out of Scope

- PWA、原生手势、暗色模式。
- 保存筛选预设；视图偏好存数据库（本次 localStorage）。
- 渠道类型切换；渠道投递历史。
- 订阅编辑页向导向化；联合会员向导（BundleWizard）改动。
- 归档列表的排序/筛选。
- 排序/筛选的数据库层下推（个人数据量级，计算后行集合上处理即可）。
- 中间档（768–1024）的专属布局重设计（仅降列，不重排）。
