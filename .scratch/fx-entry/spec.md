# 外币录入统一金额缝

Status: ready-for-agent

架构评审（2026-07-29）后续：把「外币录入」从 13 个表单的各自残缺实现收敛为一条 seam。决策见 ADR-0010。

## Problem Statement

记账用户录入外币支出时，体验与正确性取决于走哪个表单：付费记录和物品表单有完整三件套（原币+币种+折算）和汇率预填；新建订阅向导（推荐路径）的标准价直接写进主币种快照字段却旁挂币种选择器，首笔付费无折算框；联合会员打包实付有币种无折算；追加费用/收益只有单金额框（CNY-only）。所有表单提交时若折算留空，一律静默按 1:1 落库——汇率表缺币对时错误快照无警告产生。展示层全站硬编码 ¥，设了其他主币种也依旧。

## Solution

所有涉钱表单呈现同一个金额录入组件：原币金额 + 币种 + 折算主币种，失焦自动按用户汇率表预填折算值（可手改，手改不被覆盖）。提交时服务端统一按 ADR-0010 决策树兜底：同币种正当 1:1；外币优先手填值；未手填则查汇率表计算；无汇率则明确拒绝并提示两条出路（先配汇率 / 手填折算）。全站金额以用户主币种格式化显示，且处处同格式（千分位）。

## User Stories

1. 作为记账用户，我在任何涉钱表单看到同一组金额字段（原币金额、币种、折算主币种），以便不需要记每种表单各自的规则。
2. 作为记账用户，我录入外币金额并失焦后，折算框自动按我的汇率表填入折算值，以便不需要手算。
3. 作为记账用户，我手动改过的折算值不会被自动预填覆盖，以便保持「录入即事实」。
4. 作为记账用户，当币种没有汇率且我没填折算时，提交被明确拒绝并告诉我怎么解决，以便错误快照不会静默落库。
5. 作为记账用户，记录主币种支出时我可以无视折算框（留空即同额），以便本币录入保持快捷。
6. 作为记账用户，我在新建订阅向导里能为标准价录入原币金额与折算两个值，以便外币订阅的未记账周期按正确标准价估算成本。
7. 作为记账用户，我在新建订阅向导里能为首笔付费录入外币并折算，以便推荐路径下第一笔快照就是对的。
8. 作为记账用户，我编辑订阅时能看到并修改标准价的原币、币种、折算三个字段，以便创建后修正外币标准价。
9. 作为记账用户，我录联合会员时能为打包实付录入外币并折算，以便按正确金额向子会员分摊。
10. 作为记账用户，我录追加费用（配件/维修）与收益（出租/返利）时能录入外币并折算，以便物品 TCO 不受静默 1:1 污染。
11. 作为记账用户，我编辑已有付费记录时同样享有汇率预填，以便补录外币记录不用手算。
12. 作为记账用户，金额未知的存量订阅仍然可以只记服务区间不记金额（ticket 12 语义不变）。
13. 作为设了非 CNY 主币种的用户，我看到全站金额以我的主币种符号与格式显示，以便界面与我的账一致。
14. 作为记账用户，同一金额在不同页面以同一格式渲染（千分位、小数位），以便数字可读性一致。
15. 作为记账用户，我改汇率后历史记录不受影响（ADR-0004 快照不变）。
16. 作为维护者，金额解析只有一个服务端入口，以便兜底语义只在一处接受审查与测试。

## Implementation Decisions

- 新模块（client）：**金额录入组件**——受控三件套（金额/币种/折算），预填逻辑内置（失焦调用既有汇率查询 action），支持字段名前缀（向导首笔付费等场景）、`allowUnknown`（付费记录金额未知语义）、紧凑与网格两种布局。取代按字段名硬匹配的预填脚本与 PrefillForm 包装组件，两者删除；汇率查询 action 保留供组件内部使用。
- 新模块（server）：**金额解析模块**——`resolveMoney(formData, …)` 按 ADR-0010 决策树产出 `{ amount, currency, amountBase }`；服务端计算复用汇率服务的 rateToBase，两位小数；`allowUnknown` 时金额留空产出三字段全 null。
- 报错通道沿用现有 `?error=` 页面约定，新增错误码 `fx`，各页横幅文案：「币种无汇率：请先在设置→汇率添加币对，或手填折算金额」。
- 订阅标准价升级为三字段（原币 listPrice / 币种 listCurrency / 快照 listPriceBase）；订阅更新 action 补 listPrice 写入（当前不读该字段）。新建向导与编辑表单同步换三件套。schema 无需变更（列已存在）。
- 迁移范围（13 个涉钱表单）：订阅新建向导（标准价 + 首笔付费两块）、订阅编辑表单、付费记录三处（详情页内嵌新增、管理页新增/编辑、历史面板编辑）、物品新建/编辑、联合会员向导（打包实付）、追加费用面板、收益两处（详情页快捷与管理页）。
- 展示层：新格式化模块导出 `fmtMoney(n, currency)`；六处本地 fmtMoney 定义与组件库中的 fmt/fmtDate 删除（日期显示统一改用既有 isoDay）；各页面把当前用户主币种传入格式化。
- 1:1 静默兜底从所有 server action 移除；同主币种留空折算仍为正当 1:1。

## Testing Decisions

- 好测试 = 只测模块接口的外部行为（决策树分支、输出三元组），不测实现细节。
- 金额解析模块单测：决策树全部分支（同币种 1:1、手填优先、服务端查汇率计算、无汇率拒绝）、`allowUnknown` 三 null、两位小数、前缀字段解析。先行测试风格参考 cost-engine 纯函数测试。
- 金额录入组件与 13 个表单：不配单元测试（仓库无组件测试先例），以浏览器冒烟覆盖——重点路径：向导新建外币订阅（标准价 + 首笔）、无汇率拒绝横幅、预填不覆盖手改。
- 既有测试套件作为行为不变式：汇率服务、付费记录、物品、联合会员相关测试必须全绿。

## Out of Scope

- 存量 1:1 快照数据回填或标记（ADR-0010：快照即当时事实，用户自行编辑修正）。
- 汇率表本身的机制（自动刷新、API 模板、手动钉住）不做改动。
- 原币金额与折算并排展示的界面增强（展示层本次只做主币种格式化跟随）。
- 成本引擎、到期日、用量盈亏的任何语义。
