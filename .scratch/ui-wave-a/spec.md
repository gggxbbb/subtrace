# UI 波次 A：详情页热力图、快捷录入、列表盈亏信号

Status: ready-for-agent

来源：2026-08-26 全站 UI 走查（真实演示数据，桌面 1440px + 移动 390px）发现的三项体感问题，经 grill-with-docs 十二条决策收敛。本批只改日常使用路径；视觉打磨项（空面板收高、记录聚合视图、数字字号层级）排队为波次 B，不在本批。

## Problem Statement

订阅详情页被逐日日历墙主导：年付订阅渲染 ~370 个日格（`grid-cols-7` 全区间），98% 为空白，桌面端占左列 60%+ 高度，移动端需滚动 3 屏，且只有"用过/没用过"二值信息。高频动作"记一次用量"入口倒挂：须进入详情页第三屏的表单，而低频的"新建订阅"却占据控制台与列表页的显眼按钮位。订阅列表只有成本列（¥/day、¥/mo），"值不值"的盈亏信号必须逐个进详情页才能看到，尽管控制台红黑榜已有同口径计算。

## Solution

三项互相独立的改进：

1. **压缩热力图**：详情页日历网格原地替换为 GitHub 式压缩热力图——周为列横排、小格、颜色深浅编码用量，高度从 ~2000px 压到 ~150px；时间窗封顶滚动近 12 个月（53 列），更早区间由已有"历史逐周期回看"承接。
2. **快捷录入**：订阅列表行内（桌面表格 + 移动卡片）与控制台"今日可记"窄条提供 tuple 快捷按钮，一键写入今日计数记录；仅计数型。
3. **列表盈亏信号**：订阅列表新增当前区间盈亏列，口径与控制台红黑榜完全一致（`getUsageVerdict`）。

## User Stories

1. 作为用户，我想详情页的用量可视化整年一屏可见，以便不再滚动 3 屏找录入表单。
2. 作为用户，我想热力图用颜色深浅表达每天用量的多少，以便一眼看出使用规律而不只是"用过没用过"。
3. 作为用户，我想额度型订阅的热力格只在快照日出现、显示较上一快照的消耗量，以便看到的每个格子都是真实数据而非插值。
4. 作为用户，我想在订阅列表直接点快捷按钮记录今天的用量（如"1 次 @ 39"），以便不必进详情页。
5. 作为用户，我想快捷按钮给出我最近常用的 用量×单价 组合（最多 3 个），以便"练琴 2 小时"这类非 1 的用量也能一键录入。
6. 作为用户，我想在控制台看到今天还没记的计数型订阅（贵的排前面），记完后该区块消失，以便用它当日结清单。
7. 作为家庭共享的受益人，我想"今日可记"只看我自己的记录缺口、快捷录入写在我名下，以便与 ADR-0003 的按人切片一致。
8. 作为用户，我想在订阅列表直接看到每个订阅当前区间的盈亏金额（盈青/亏红/成本未知灰/未跟踪 "—"），以便回答"哪个该砍"不用逐个进详情。
9. 作为手机用户，我想以上三项在移动端同样可用（卡片行内按钮、44px 触控），以便手机完成完整录入闭环。

## Implementation Decisions

**热力图（ticket 01）**

- 新组件替换 `UsagePanel.tsx:356` 的日历网格（面板编号/位置不变，详情页其余面板不动）。周为列（周一为首，北京墙钟），7 行 × ≤53 列。
- 时间窗：固定渲染「今天」往前 53 周；与盈亏面板的周期导航解耦（历史回看只影响盈亏，不影响热力图）。
- 语义按用量类型分裂：计数型 = 当日 Σ quantity；省钱型 = 当日已省金额；额度型 = 仅快照日有格，值 = 较上一快照的消耗（REMAINING 取下降量、USED 取增量；消耗 ≤0 的格子按空白渲染，tooltip 如实显示差值）。UI 不编造引擎没有的逐日归因。
- 深浅刻度：5 档（0 = 空白；非零值按窗口内分位数 25/50/75/100 分档），用 accent 色透明度阶梯，不引入新色。
- 交互：仅 `title` 悬浮提示（日期 + 数值），沿用溢出截断的提示先例；无点击跳转。

**快捷录入（ticket 02）**

- tuple 去重逻辑从 `UsagePanel.tsx:104-110` 抽为共享纯函数（全历史去重、最近优先），详情页与新组件共用，不产生第二份逻辑。快捷按钮展示 cap 3（详情页表单维持 6 个不变）。
- 列表行内：桌面表格行与移动卡片（44px 触控底线、flex-wrap，沿用 ui-polish 既定）各放 ≤3 个 tuple 按钮；仅 `usageKind === COUNT` 且 `status === ACTIVE` 的订阅显示。省钱/额度型不加任何快捷钮。
- 点击 = server action 写入 DELTA 记录：`date` = 服务器北京墙钟今日（不用客户端时区），quantity/unitPrice 取按钮元组，unitPrice 为空时沿用现有继承链（记录默认 → 订阅默认）。
- 控制台"今日可记"窄条：KPI 行下新增 panel，列出今天（北京墙钟）当前用户尚无 DELTA 记录的计数型活跃订阅 + 各自 tuple 按钮；按日均成本降序、cap 5；无待记或无计数型订阅时整个 panel 不渲染。数据从 `getDashboardData` 一处聚合出，不加新请求。
- 失败路径沿用全站 `?error=` 查询参数先例。

**列表盈亏信号（ticket 03）**

- 订阅列表新增盈亏列：`getUsageVerdict(sub, records, today, userId)` 当前区间口径，与控制台红黑榜同一函数同一参数形态（dashboard.ts:140-166），不引入第二套口径。
- 呈现：金额 + 色——盈 `--income` 青、亏 `--destructive` 红、`costUnknown` 灰显并注明、未启用用量显示 "—"。移动卡片视图同位置。
- 性能：列表页用量拉取按 dashboard 的 `Promise.all` 模式并行，STACKED 订阅先 `reconcileAutoPacks`（同 dashboard.ts:132-139），禁止循环内串行 await（ui-hardening 已修过一次 N+1）。
- 排序：`list-query` 排序字段新增「盈亏」，升降序作用于派生后的行集合（与现有日均/月均排序同机制）。

## Testing Decisions

沿用仓储缝测试风格（纯函数优先；服务缝用真实 prisma 测试库）。UI 视觉不做自动化（仓库无组件测试栈），浏览器 375/1440 双宽度冒烟。

- **热力图分桶（纯函数）**：日期 → 周列归位（周一为首、北京墙钟）；53 列封顶截断；计数/省钱当日求和；额度型快照差值（REMAINING 降量、USED 增量、消耗 ≤0 不编码）；5 档分位刻度（空窗、单一非零值、均匀分布）。
- **tuple 函数（纯函数）**：全历史去重、最近优先、cap 3；空历史返回空数组。
- **"今日可记"过滤（纯函数或服务缝）**：北京墙钟今日边界（23:59 → 次日 00:00 翻转）；按用户切片（受益人只见自己缺口）；已记即消失；非计数型不出现。
- **快捷录入服务缝**：写入记录字段（日期、元组、单价继承链）；COUNT 以外类型拒绝。
- **盈亏信号**：列表渲染用 verdict 与红黑榜同值（同一 fixture 下两处一致）；`costUnknown` 灰显分支。
- **冒烟**：浏览器走「列表 +1 → 详情页出现今日记录 → 热力图今日格点亮 → 控制台待记消失 → 列表盈亏列变色」全链路。

## Out of Scope

- 波次 B 三项：空面板收高、记录管理聚合视图、数字字号层级（排队，不在本批）。
- 热力图格子的点击跳转；历史区间的热力图（由历史回看承接）。
- 省钱型/额度型的快捷录入（不存在真实的一键值）。
- 全局悬浮按钮、键盘快捷键等新交互范式。
- 联合会员页、物品页的盈亏/信号列。
- 移动端独立方案（同权同方案）。
- 暗色模式专项调整（语义 token 已双主题，新增 UI 只写语义类）。
