# 用量换壳：录入台 + 滑动窗 headline + 决策树向导

Status: ready-for-agent

Grilling 产出：滑动窗决策见 ADR-0014 与 CONTEXT.md「滑动窗口 / 用量周期」词条（2026-09-02）。三轮共十二问（Q1–Q12）已在 grill 会话中确认：Q4 录入卡点 = 找入口 / 填表单 / 补记三者全占；Q5–Q7、Q11–Q12 采纳推荐答案；Q8 价值未知态纳入二期（ticket 04）。

## Problem Statement

用户实际使用半年后，用量功能的三个真实摩擦点：

1. **录入动线长**：记一笔用量要「找到哪个页面哪个位置」。事实：快捷入口（今日可记 / 列表行内 tuple 钮）只覆盖计数型，而库里三口径各有一个订阅在用；额度型、省钱型每次录入都必须钻进订阅详情页找到对应录入卡。半年共 50 条记录（约每周 2 条），其中计数型 41 条（82%）。补记（非当天录入）无任何快捷路径——快捷钮只能写今天。
2. **配置决策负担重**：向导已有概念讲解与示例卡片，但「这东西该用什么类型、各种参数怎么写」的决策仍完全压在用户身上。卡点不在解释不够，在决策本身。
3. **红黑榜读不懂**：榜上每行只有名称 + 一行公式残片 + 金额，右上角一个含糊的「本区间」——全榜没有任何一处标注周期起止，且每个订阅的「本区间」各不相同（各自的用量周期），却并列排序。此外固定周期窗口有固有漂移：周期初数字难看（成本在摊、用量未攒）、周期末好看，同一订阅的数字含义随日期变化。

值得保留的现状：引擎层（ADR-0013 双引擎、ADR-0012 FEFO）与数据模型是半年迭代中做对了的部分，全部原样保留。`periodCost` / `usageInPeriod` / `usageValue` 天然接受任意 `[start, end)` 窗口——滑动窗不需要新引擎。本 feature 只换用户侧外壳。

## Solution

三件套 + 一项二期：

**① 全口径录入台**：控制台设常驻「记用量」区，平铺所有已开用量跟踪的活跃订阅（不再只计数型）。计数型 tuple 一键 + 可展开自定义（数量/单价/日期）；额度型展开录快照（RESET 收剩余或已用，STACKED 只收剩余——沿用记录页的形态收敛）；省钱型录已省金额（增量/累计求差语义沿用 `addSavings`）。**日期默认今天、可改过去**——补记是一等场景。今日已记的计数型显示「已记」标记而非消失。本区取代现有「今日可记」窄条（clean cutover）。

**② 滑动窗 headline（ADR-0014）**：用量盈亏的对外判定统一为**以今天为终点的固定 30 天滑动窗口**：净盈亏 = 窗口内用回价值 − 窗口内摊销成本，三口径仅价值计量不同（次数×替代单价 / Σ已省 / 快照差值消耗×折算单价）。红黑榜每行标签写死「近30天」；周期事实降级为附属信号——重置/到期倒计时 chip、窗口内浪费事件标注；详情页历史逐周期回看保留原位（引擎按周期归因的语义不变）。窗口长度固定 30 天，不可配。

**③ 决策树向导**：向导的类型选择步替换为自然语言决策树——「这个订阅怎么给你价值？」（按次使用 / 每月给定量 / 消费折扣）映射三口径并预填；额度型追问「额度怎么发？」（每期重置 / 逐期累积）映射发放形态。参数区按口径收敛，每项参数附「填什么、不填会怎样」与默认值。

**④（二期，ticket 04）**：计数型允许无单价记录，headline 显示「价值未知」——先开始、边用边补，仿 `costUnknown` 先例。

## User Stories

1. 作为用户，我想控制台首页就有一个常驻「记用量」区，平铺我所有开了用量跟踪的订阅，以便记一笔不再需要找页面。
2. 作为用户，我想计数型订阅在录入台一点 tuple 就记上（与列表行内同一套按钮），以便日常零思考。
3. 作为用户，我想额度型订阅在录入台展开就能抄一个剩余/已用快照（STACKED 只收剩余），以便不用进详情页辨录入卡。
4. 作为用户，我想省钱型订阅在录入台直接填「已省」金额，语义与详情页一致（累计值自动求差）。
5. 作为用户，我想录入时能改日期（默认今天），以便事后补记不用猜哪笔补在哪。
6. 作为用户，我想今天已记过的计数型订阅显示「已记」标记而不是消失，以便确认自己记过。
7. 作为用户，我想移动端录入台与桌面同权同方案（44px 触控），以便手机上也能随手记。
8. 作为用户，我想录入后控制台与详情页数字即时一致（同一 `usageById` 装配），以便不怀疑看到旧数。
9. 作为用户，我想红黑榜每行 headline 是「近30天」净盈亏（付了 X / 用回 Y / 净 Z），以便三口径横向可比、且永远知道说的是哪段时间。
10. 作为用户，我想额度型订阅行内仍看到重置/到期倒计时与窗口内浪费事件（「9月1日到期焚毁 2GB」），以便截止压力与浪费不丢。
11. 作为用户，我想详情页主判定与红黑榜同口径，历史逐周期回看保留在原有导航里，以便复盘旧账。
12. 作为用户，我想成本未知 / 快照陈旧的灰显与变色语义原样保留，以便数据残缺时仍能识别。
13. 作为用户，我想新订阅不足 30 天时窗口标注实际天数（「近 12 天」），以便不被看似完整的数字误导。
14. 作为受益人，我想滑动窗判定的成本仍按权重切份额（沿用现状），以便多人分摊语义不变。
15. 作为用户，我想给新订阅开用量跟踪时回答「它怎么给你价值」三个选项即可完成选型并预填参数，以便不需要懂「计数型/额度型/省钱型」 taxonomy。
16. 作为用户，我想参数区每项都告诉我「填什么、不填会怎样」并给默认值，以便不用查文档。
17. 作为用户，我想编辑已有配置时跳过决策树直接改参数，以便老路径不受打扰。
18. （二期）作为用户，我想计数型订阅没想好单次市价也能先记次数（headline 显示「价值未知」），以便先养成记录习惯、单价后补。

## Implementation Decisions

- **录入台（ticket 01）**：数据并入 `getDashboardData`（`usageById` 已全量装配，tuple 复用 `usageTuples` cap 3）。写路径复用现有 server actions（`addUsageAction` / `addQuotaSnapshotAction` / `addSavingsAction`），扩展日期入参（默认服务器北京墙钟今日，允许过去日期；守卫不变）。「今日可记」窄条删除，其 `pendingQuickLog` 逻辑并入录入台的「已记」标记判定。列表行内 tuple 钮不动。
- **滑动窗（ticket 02）**：新增纯函数 `rollingVerdict`（与 `streamVerdict` 同级），窗口 = `[今天−30d, 今天]` 北京墙钟。COUNT/SAVINGS 直接以窗口调 `usageValue` / Σ增量 + `periodCost`；QUOTA 窗口内消耗按相邻快照差归因（与 `heatmap.ts` 同粒度近似，差值逻辑抽共享函数），折算单价 = 窗口与各用量周期重叠天数加权的「周期成本 ÷ 总额度」。STACKED 的窗口内浪费事件由 `projectPackLedger` 输出按日期过滤。`dispatchVerdict` 增 rolling 变体；周期 verdict 保留供历史回看与倒计时。headline UI：红黑榜行 + 详情页盈亏网格主数字切换，倒计时 chip / 浪费事件 / 快照陈旧 / 成本未知语义保留。
- **决策树向导（ticket 03）**：`UsageWizard` 的「类型」步替换为决策树（价值形态三选 → 额度形态二选），选项卡沿用现有示例语料；「概念」步同步收敛（类型术语降级为小字标注）。参数步按口径只露必要字段，每项附一句「不填会怎样」+ 默认值；编辑已有配置（`initialKind` 存在）直接进入参数步。确认步不变。
- **价值未知（ticket 04，二期）**：COUNT 无单价记录入库放行（写路径守卫放宽），`rollingVerdict` / `streamVerdict` 输出 `valueUnknown` 态（仿 `costUnknown`），headline 灰显「价值未知」、次数与成本照常显示。

## Testing Decisions

好测试标准：只测外部行为，沿用仓储缝测试风格（真实 prisma 测试库，`fileParallelism: false`）。

- **rollingVerdict 缝（新纯函数）**：三口径窗口价值与成本、QUOTA 跨用量周期的重叠天数加权折算、窗口边界（北京墙钟 today−30d 翻转）、不足 30 天标注实际天数、STACKED 窗口内浪费事件过滤、空记录/空成本段边界。先行例子：`usage/ledger.test.ts`、`cost-engine/index.test.ts` 风格。
- **服务缝（prisma 测试库）**：`dispatchVerdict` rolling 变体装配（含受益人份额切片）、带日期写路径（补记落库、未来日期拒绝）、「已记」标记判定。先行例子：`usage/service.test.ts`。
- **冒烟**：dev server 起服务，浏览器走「控制台录入台对三口径各记一笔（含一笔改日期补记）→ 红黑榜『近30天』数字变化且与详情页一致 → 向导三问给一个新订阅完成开通」。

## Out of Scope

- 窗口长度可配（Q12 已决固定 30 天——可切换会引入「这是哪个窗」的新困惑）。
- 引擎层任何重构（ledger / stream / period / pack-ledger 原样保留）。
- 额度型逐日精确消耗归因（快照粒度近似已是 ADR-0012/热力图共识）。
- 快照陈旧、到期预警的推送提醒（沿用原位展示先例）。
- 用量脚本机制变更（STACKED `{remaining}` / RESET `{used,total?}` 契约不变）。
- 价值未知态的完整实现放二期 ticket 04；ticket 01/02 不为它预留 UI 分支。

## Further Notes

- 01 与 02 都触及 `dashboard/page.tsx` 与 `getDashboardData`：建议按序实施（先 01 后 02）或同人连续完成，避免并行冲突。03 仅触及 `UsageWizard.tsx`，与 01/02 无冲突面。
- 滑动窗与热力图是两种互补视图：热力图看 53 周分布形态，headline 看近 30 天净额——两者粒度与归因近似一致（快照差值法），不矛盾。
- 「记一笔的时间 < 看懂一笔的时间」是本 feature 的验收直觉：冒烟时若录入台任何口径超过两步（点开 + 填写 + 提交中的两步），视为未达标。
